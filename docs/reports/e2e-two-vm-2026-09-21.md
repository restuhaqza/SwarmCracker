## 4. Fixes Applied (working tree, uncommitted)

| # | Severity | File(s) | Bug → Fix |
|---|---|---|---|
| F1 | S1 | `cmd/swarmcracker/cmd_init.go`, `cmd_join.go` | Invalid `ReadWritePath=` (singular, regression from `216cfdc`) ignored by systemd, so `ProtectSystem=strict` left `/var/lib/swarmkit` read-only → daemon died. → Correct `ReadWritePaths=` + `PrivateTmp=true` + cache/CNI dirs. |
| F2 | S1 | same | `Type=notify` with a daemon that has no sd_notify support → 90 s start timeout. → `Type=simple`. |
| F3 | S1 | `cmd/swarmcracker/cmd_join.go` | Token validator required `SWMTKN-1-{role}-...`; every real SwarmKit token was rejected. → Accept `SWMTKN-1-{hash}-{secret}`. |
| F4 | S1 | `pkg/swarmkit/vmm.go` | Firecracker started with `exec.CommandContext(callerCtx)`; ctx was canceled right after `Start()` → **every microVM SIGKILLed instantly**. → `exec.Command`, lifetime managed by Stop/ForceStop/Remove. |
| F5 | S1 | `pkg/image/detector.go`, `init.go`, `wrapper.go` | Alpine `/sbin/init` → busybox was "preserved"; the rewritten `/etc/inittab` never ran the OCI ENTRYPOINT/CMD, so the VM ran no workload. → Detect busybox init and inject the OCI-aware tini wrapper. |
| F6 | S1 | `pkg/image/wrapper.go` | Wrapper emitted `tini -g <seconds>`, but `-g` is a **boolean** flag → tini exec'd the number `10` → `exec 10 failed` → PID 1 panic → reboot loop. → Use `-s -g` (no numeric arg). |
| F7 | S1 | `pkg/image/wrapper.go` | Wrapper emitted `tini -e QUIT`; tini's `-e` needs a **numeric** signal → `Not a valid option for -e: QUIT` → panic. → Map signal names to numbers (`SIGQUIT` → `3`). |
| F8 | S2 | `pkg/image/wrapper.go` | Wrapper wrote `/sbin/init` through the pre-existing symlink to busybox (would corrupt busybox). → `os.Remove` first. Also mount `devtmpfs` and configure `eth0` from the kernel `ip=` param. |
| F9 | S2 | `cmd/swarmcracker/cmd_setup.go` | `setup config --non-interactive` ignored the flag and failed `kernel_path is required`. → Apply flag values (flags carry defaults). |
| F10 | S2 | `cmd/swarmcracker/cmd_setup.go` | `setup install --download-kernel` used the obsolete S3 layout `firecracker-ci/<major.minor>/...`; bucket now uses dated prefixes. → List `firecracker-ci/` and pick the newest arch kernel. |
| F11 | S2 | `Makefile` | `swarmd-firecracker` / `swarmcracker-agent` targets compiled only `main.go`, omitting `flags.go`/`run.go` → `make all` failed. → Build the package path. |
| F12 | S1 | `cmd/swarmcracker/cmd_init.go`, `cmd_join.go`, `cmd/swarmd-firecracker/run.go`, `cmd_setup.go` | `cluster init/join` never passed `--enable-cni` → every task rejected `network support is unavailable`. → `--enable-cni` (default true), CNI writable paths, graceful degradation if plugins are missing, and `setup install --download-cni`. |
| F13 | S2 | `pkg/image/preparer.go` | `handleVolumeMount` panicked on a nil `VolumeManager`; crashed the whole `pkg/image` test binary. → Return a clear error. |
| F14 | S2 | `pkg/image/wrapper_test.go` | Tests asserted the buggy `-g <n>` / grace-period contract. → Updated to the corrected tini contract + added signal-mapping tests. |

## 5. Open Issues (not fixed)

| # | Sev | Area | Summary |
|---|---|---|---|
| O1 | S2 | `vm` command | Foreground `swarmcracker vm create` treats `RUNNING` as completion and **tears the VM down immediately**; only `-d` keeps it alive. |
| O2 | S2 | CNI / `vm create` | Direct `vm create` with CNI creates a TAP but does **not** attach a network interface to the Firecracker VM → guest has no `eth0` (TAP NO-CARRIER). The SwarmKit path attaches a default TAP correctly. |
| O3 | S2 | lifecycle | Removing a service can leave its microVMs running (observed leaks of 1–3 VMs). No TAP/socket reaping in some paths. |
| O4 | S3 | `vm list` | Shows stale entries with `PID 0` / "Running ✓" after the VM has exited. |
| O5 | S3 | cluster | Re-joining a worker creates a new node ID; the old record remains as `DOWN` (no automatic pruning/decommission). |
| O6 | S3 | `node` cmd | `node drain <id>` rejects the truncated ID displayed by `node ls`; the full ID is required. |
| O7 | S3 | setup | `setup check` looks for `/etc/swarmcracker/config.yaml`, but `cluster init` writes `manager-config.yaml`; the check reports a false "config missing". |
| O8 | S3 | tests | `TestCreateExt4Image_*` require `e2fsprogs`/`mkfs.ext4` on the host; they fail in minimal environments (environmental, not a code bug). |
| O9 | — | operational | Docker Hub (`TOOMANYREQUESTS`) and AWS ECR Public (`Rate exceeded`) anonymous pull limits cause image-pull failures and task churn. Prefer authenticated pulls or a local registry. |

## 6. How to Reproduce

```bash
# Build (Makefile target now works too)
make all

# Two VMs
multipass launch 22.04 --name sc-master --cpus 2 --memory 3G --disk 20G
multipass launch 22.04 --name sc-worker --cpus 2 --memory 3G --disk 20G

# Provision each node (copy binaries first)
sudo install -m0755 swarmcracker swarmd-firecracker swarmctl /usr/local/bin/
sudo install -m0755 swarmcracker-cni /opt/cni/bin/swarmcracker-cni
sudo swarmcracker setup install --download-kernel --download-rootfs --download-cni
sudo swarmcracker setup network
sudo swarmcracker setup config --non-interactive

# Cluster
sudo swarmcracker cluster init --advertise-addr <MASTER_IP>:4242
sudo swarmcracker cluster join <MASTER_IP>:4242 --token SWMTKN-1-... --advertise-addr <WORKER_IP>:4242

# Deploy and verify
sudo swarmcracker service create --name web --image nginx:alpine --replicas 1
sudo swarmcracker service ps web
curl http://<guest-ip>/           # -> <title>Welcome to nginx!</title>
```
